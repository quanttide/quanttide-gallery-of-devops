# 文件移动与改名

文件移动与改名的四类坑：`git mv` 的适用范围、改名后内容改动漏暂存、空目录根本不被追踪、删已搬走目录时的报错噪音。共同点是 git 只跟踪它已知的路径，路径之外的动作不会自动留下提交记录。

四条都发生在本地，且在提交前就能发现：前两条决定这次改名提交是否完整，后两条决定你对「有没有变动」的判断是否准确。

## `git mv` 报「fatal: 不在版本控制之下」

现象：`git mv` 报「fatal: 不在版本控制之下」。

因：源或目标未 tracked，或要跨子模块移动；另外目标未 `git add` 前 `git mv` 同样报错——所以报错点可能在源路径，也可能在目标路径。

做法分三种情况：

- 未跟踪文件用 `mv`，不用 `git mv`
- 跨子模块＝源仓删、目标仓建，不能用 `git mv`
- 目标先 `git add`，再 `git mv`

## 改名后只暂存了 rename

现象：`git mv` 改名后只暂存了 rename，同文件的内容改动漏在工作区。

因：暂存区里只有改名这一个动作，HEAD 文件名是新的、内容是旧的——文件改了名，改动本身却还在工作区。

做法：改名类提交收尾必须核对 staged diff 含内容改动，确认 rename 和内容改动都在暂存区里，再提交。

## git 不追踪空目录

现象：语境仓里的空 `journal/`、`profile/` 删掉不会有任何提交变动。

因：`git` 不追踪空目录，目录本来就不在版本控制里。

做法：别把它当成「删了东西」，也不要拿「没有提交变动」判断删除是否成功。

## 删已被 `git rm` 或搬走的目录

现象：删除已被 `git rm` 或搬走的目录时，`rmdir` 报 No such file（exit 1）。

因：路径已经被 `git rm` 删掉或被搬到别处，早已不存在；报错只反映文件系统状态，不是 git 层面的失败。

做法：可忽略；批量脚本别把它当失败中断——目录在 git 层面早已不存在，`rmdir` 的退出码 1 只是脚本里的噪音。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| `git mv` 报「fatal: 不在版本控制之下」 | 源或目标未 tracked、跨子模块移动、目标未 `git add` | 未跟踪文件用 `mv`；跨子模块＝源仓删、目标仓建；目标先 `git add` |
| 改名提交缺内容改动 | 只暂存了 rename，内容改动漏在工作区 | 收尾核对 staged diff 含内容改动 |
| 删空目录没有提交变动 | git 不追踪空目录 | `journal/`、`profile/` 这类空目录删掉本来就没有提交，别当成「删了东西」 |
| `rmdir` 报 No such file（exit 1） | 目录已被 `git rm` 或搬走 | 忽略，批量脚本不要当失败中断 |
