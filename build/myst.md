# MyST 写入

MyST 的 tab 块由成对的围栏组成，批量生成内容时最容易漏闭合。本文记录写入 MyST 标签的规则，以及写完后的检查流程。

## 规则

- `{tab-set}` 与 `{tab-item}` 围栏必须成对闭合，且两者层级不同：`tab-item` 在 `tab-set` 之内
- 批量生成时极易漏闭合，写完必须跑围栏配对检查
- README 这类直接在 GitHub 渲染的页面不放 MyST 标签

## 为什么

批量生成时围栏成段输出，漏掉闭合不会立刻报错，渲染时才暴露问题，所以配对检查不能省。

层级不同的含义是 `{tab-set}` 包裹若干 `{tab-item}`，两者围栏数量要对应，不能混在同一层或只写开不写闭。

GitHub 直接渲染的页面不识别 MyST 标签，放了 MyST 标签只会原样显示为文本，因此这类页面保持纯 Markdown。

## 工作流

1. 写作 tab 内容，`{tab-set}` 内逐个放 `{tab-item}`，每个围栏写完立即闭合。外层指令的围栏要比内层长（`tab-set` 用四反引号、`tab-item` 用三反引号）：

````{tab-set}

```{tab-item} 标签一
内容
```

```{tab-item} 标签二
内容
```

````

2. 写完跑围栏配对检查，确认 `tab-set` 与 `tab-item` 数量匹配、层级正确。
3. 检查目标页面的渲染环境：README 这类直接在 GitHub 渲染的页面不放 MyST 标签。

## 常见错误

| 现象 | 原因 | 处理 |
|------|------|------|
| tab 不显示、围栏原文暴露 | 批量生成时漏闭合 `tab-set` 或 `tab-item` | 跑围栏配对检查，补齐闭合 |
| 围栏闭合了但渲染仍异常 | `tab-item` 未放在 `tab-set` 之内，层级错误 | 保证 `tab-item` 在 `tab-set` 内 |
| README 里 MyST 标签原样显示 | GitHub 直接渲染的页面不识别 MyST 标签 | 这类页面不放 MyST 标签，保持纯 Markdown |
